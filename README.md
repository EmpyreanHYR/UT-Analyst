# 超声波智能辅助检测系统 (UT-Analyst)

`UT-Analyst` 是一个基于 `Python 3.10+`、`PyQt5`、`PyQtGraph`、`NumPy` 的超声检测仿真软件，采用 `MVC` 架构，重点面向 A-Scan 波形监看、闸门检测、缺陷记录和报告追溯。

## 1. 当前能力概览

### 1.1 核心检测能力（P0）

- 实时采集控制：`开始检测`、`停止检测`、`冻结`、`单次采样`
- 波形辅助：`峰值保持`、`参考波形捕获/清除`
- 触发模式：`自动`、`闸门触发`
- 闸门检测：`Start / Width / Level` 三参数线性闸门
- 测量读数：双游标 `A/B`（图上可见标签）、`Δt/Δd` 实时显示
- 单位切换：`时间(us)` / `深度(mm)`，闸门输入自动换算
- 校准流程：`声速校准`、`零点校准(Probe Delay)`、校准文件 `保存/加载`
- 判定一致：有缺陷记录或当前触发即判 `不合格`

### 1.2 数据追溯能力

- 缺陷列表支持删除、清空、重编号
- 每条缺陷记录自动抓取对应波形截图
- 报告导出为 `HTML`，包含总览图 + 缺陷分项截图

### 1.3 信号处理功能

- **FFT频谱分析**：实时频谱显示，峰值频率识别，频谱测量
- **数字滤波器**：带通、低通、高通滤波器，可调截止频率和阶数
- **信号平均**：多次采样平均，提高信噪比（2-64帧可调）

### 1.4 数据分析功能

- **缺陷统计分析**：缺陷总数、深度分布、波幅分布统计
- **DAC曲线**：距离-波幅校正曲线，缺陷超限判定
- **验收标准判定**：按可编辑规则表对缺陷逐条评级并判废，给出理由与整体结论
- **指示长度测量**：由 B-Scan 帧历史用 6 dB 落差法测量指示长度与指示高度
- **跨会话缺陷跟踪**：按深度归组历次会话的缺陷记录，给出重复出现位置与变化量
- **缺陷类型提示**：按规则评分给出类型候选（只作提示，不写入判定结论）
- **波形特征提取**：信号统计特征、过零率、能量等参数提取
- **信号对比**：两个信号的差异分析，相关系数计算

### 1.5 报告功能

- **标准模板库**：支持通用、NB/T 47013、GB/T 11345、ASME等标准
- **报告定制化**：公司信息、检测人员、项目信息、备注
- **检测参数嵌入**：自动嵌入采样率、探头频率、增益等参数

### 1.6 用户体验优化

- **快捷键系统**：F1-F6功能键，Ctrl组合键，Delete删除键
- **界面布局记忆**：窗口位置、大小、Dock布局自动保存/恢复
- **快捷键帮助**：F1键显示所有快捷键一览表

### 1.7 数据追溯与回放

- **会话持久化**：SQLite 保存检测会话、缺陷、报告和波形分块索引
- **完整回放**：支持会话选择、逐帧、倍速、跳转和截图还原
- **PDF 报告**：HTML/PDF 使用同一模板，报告内容包含 SHA-256 哈希

### 1.8 高级 UT 分析

- **多闸门**：Gate A/B/C 独立启停、门限和触发状态
- **TCG**：分段距离-增益补偿，支持表格录入和波形补偿
- **B/C-Scan**：B-Scan 历史成像、C-Scan 光栅位置成像
- **耦合与探头监测**：按底波幅值滑动统计提示耦合不良与波动异常
- **采集适配**：仿真、回放、伪硬件和厂商适配器统一接口

### 1.9 本地权限与审计

- **本地用户**：管理员、工程师、操作员、查看者四种角色
- **密码安全**：PBKDF2-HMAC-SHA256 加盐存储和失败锁定
- **审计链**：前序哈希链可检测历史记录篡改
- **报告签名**：记录签署用户、时间和报告文件哈希

## 2. 环境与启动

### 2.1 依赖环境

- Python：`3.10+`
- 依赖：`requirements.txt`

### 2.2 安装依赖

```bash
pip install -r requirements.txt
```

### 2.3 启动程序

```bash
python main.py
```

首次启动时创建本地管理员账户；后续启动输入用户名和密码。数据默认保存在
`data/` 目录，包括 `ut_analyst.db` 和会话波形分块。

## 5. 可操作事项（建议按顺序）

### 5.1 基础检测流程

1. 点击 `开始检测`
2. 调整 `增益/声程/频率/刷新间隔/声速`
3. 点击 `应用参数`
4. 拖动闸门与门限，观察峰值标记与右侧定量结果

### 5.2 冻结与单次采样

1. 点击 `冻结` 暂停画面更新（便于精读当前波形）
2. 点击 `单次采样` 获取一帧新波形
3. 取消 `冻结` 恢复实时刷新

### 5.3 参考波形与峰值保持

1. 在稳定状态点击 `捕获参考`
2. 开启 `峰值保持` 观察包络上包络轨迹
3. 必要时点击 `清除参考`，关闭 `峰值保持`

### 5.4 触发模式

1. `自动`：每个采样周期都刷新显示
2. `闸门触发`：仅当闸门内达到触发条件时更新显示（模拟触发采样）

### 5.5 游标读数

1. 拖动波形图中的 `A/B` 游标线
2. 在右侧查看 `A`、`B`、`差值Δ`、`深度差Δd`
3. 切换 `显示单位` 可在 `us/mm` 两种读数间切换

### 5.6 缺陷记录与清理

1. 点击 `开始记录`（未开始记录时不会写入历史）
2. 触发后自动入表（带编号、深度、波幅）
3. 右键表格可 `删除选中记录` 或 `清空历史记录`
4. 也可用键盘 `Delete` 删除选中历史行（`实时` 行不可删）

### 5.7 校准流程

1. 设置 -> `声速校准`：输入实测往返时间与已知厚度
2. 设置 -> `零点校准`：输入实测时间与对应厚度
3. 设置 -> `保存校准` 或 `加载校准`（JSON）

### 5.8 报告导出

1. 先执行检测并记录缺陷
2. 点击 `生成报告` 打开预览窗口
3. 在预览窗口点击 `保存报告`
4. 输出为 `HTML`，可直接浏览器打开

### 5.9 频谱分析

1. 按 `F5` 或 视图 -> `频谱分析面板` 显示频谱分析面板
2. 点击 `计算FFT` 查看当前波形的频谱
3. 调整 `FFT点数` 和 `窗函数` 优化频谱显示
4. 使用 `数字滤波器` 对信号进行滤波处理
5. 支持 `带通`、`低通`、`高通` 三种滤波器类型

### 5.10 缺陷统计分析

1. 按 `F6` 或 视图 -> `缺陷统计面板` 显示统计面板
2. 点击 `刷新统计` 更新缺陷统计数据
3. 查看 `缺陷总数`、`深度范围`、`平均深度`、`平均波幅`
4. 查看 `验收标准`、`判定结论` 和 `验收判定明细`
5. 查看 `深度分布图` 和 `波幅分布图`
6. 查看 `DAC曲线` 和缺陷点位

### 5.12 设置验收标准与查看判定

1. 打开 设置 -> `验收标准`
2. 选择标准（`GB/T 11345-2013`、`NB/T 47013.3-2015`、`通用`）与验收等级
3. 填写 `工件壁厚`（mm）和 `扫查步距`（mm），点击 `OK`
4. 缺陷表末列 `判定` 立即刷新；统计面板显示 `验收标准` 与 `判定结论`
5. 生成报告时结论由验收规则引擎给出，报告含 `验收判定明细` 表

判定说明：

- 每条缺陷先用相对 DAC（或参考回波）的分贝偏移落入 Ⅰ / Ⅱ / Ⅲ / 判废区得到等级，再按工件壁厚分档核对指示长度限值，取较劣者作为该条等级；等级不劣于验收等级判 `合格`，否则 `不合格`；特征不足（既无分贝偏移也无指示长度）判 `待定`。
- 整体结论：有一条 `不合格` 即 `不合格`，否则若有 `待定` 即 `待定`，其余 `合格`；没有缺陷记录但当前帧闸门触发时仍判 `不合格`。
- 内置三套标准的判据线（评定线 / 定量线 / 判废线）与长度限值均为**示例占位值**，正式使用前必须对照标准原文校核后修改 `app/model/acceptance_criteria.py` 中的规则表。
- 标准或等级切换写入审计事件 `criteria.change`。

### 5.13 指示长度测量与耦合监测

- **指示长度**：程序在 Gate A 深度窗内的 B-Scan 帧历史上按 6 dB 落差定位指示端点，`指示长度 = 端点帧序号差 × 扫查步距`；斜探头另给出深度方向的 `指示高度`。数值随缺陷记录保存，并显示在报告的缺陷卡片中。
- **前提**：位置轴按 `扫查步距 × 帧序号` 折算，不是编码器实测位置，扫查步距填错或扫查速度不均会使读数偏大或偏小；指示触及扫查范围边界时测量偏小，程序会提示扩大扫查范围后复测。
- **耦合监测**：实时采集时按底波幅值的滑动窗口给出 `正常 / 耦合不良 / 波动异常 / 数据不足`，进入前两种状态时状态栏弹出警告。监测不参与判定，也不自动停止采集；每次开始采集重建基准，检测前先在完好区域空扫一小段更可靠。

### 5.14 跨会话缺陷跟踪与类型提示

- **跨会话跟踪**：视图 -> `跨会话缺陷跟踪`（按报告配置中的工件名筛选）。程序把历次会话的缺陷记录按深度 ±5 mm 归组，表格列出组号、平均深度、会话数、波幅变化、长度变化与说明；报告新增 `跨会话重复缺陷` 一节。
- 位置接近不等于同一条缺陷，跟踪结果只是复检对比的线索，不能据此直接判定缺陷在扩展。
- **类型提示**：按规则评分给出候选类型（气孔/点状夹渣、条状夹渣、裂纹、未熔合/未焊透、分层），匹配度最高且不低于 50% 才显示，否则显示 `类型不明`。提示出现在统计面板的判定明细行和报告 `验收判定明细` 表的 `类型提示` 列，**不写入**判定结论。

## 6. 数据文件说明

  view/

## 8. 注意事项

- 采集层提供仿真源、回放源和厂商硬件适配接口，三类来源共用同一处理、记录和回放流程。
- 报告判定规则：先由验收规则引擎逐条评级，再有缺陷记录或当前帧触发即判定 `不合格`。
- 内置标准的判据数值与类型提示的规则权重都是示例 / 经验值，正式使用前须按标准原文校核并修改。
- 提示类功能（耦合监测、类型提示、跨会话跟踪）只作参考，不写入合格与不合格结论。
- 如果发现界面“无变化”，先检查：
  - 是否处于 `冻结` 状态
  - 触发模式是否设置为 `闸门触发` 且当前未触发
  - 是否点击了 `开始检测`

## 9. 说明书截图维护

在可运行 PyQt5 与 PyQtGraph 的环境中执行以下命令，可自动生成登录、主界面、参数面板、频谱、统计、缺陷表、验收标准与判定明细、跨会话跟踪、多闸门/TCG、B/C-Scan、回放、报告、审计、设置菜单、滤波器参数与快捷键帮助截图，以及闸门/游标标注截图：

```powershell
$env:QT_QPA_PLATFORM = "windows"
$env:QT_OPENGL = "software"
python scripts/generate_manual_screenshots.py
```

生成结果写入 `Direction/image/`，随后在 `Direction` 目录执行两次 `xelatex main.tex` 更新说明书 PDF。

验收判定与跨会话跟踪的截图使用脚本里的示例缺陷数据（`DEMO_DEFECT_SNAPSHOTS` / `DEMO_TRACKING_RECORDS`），数值由真实的规则引擎算出，修改示例数据后重新执行即可更新插图。

缺陷表插图（`defect.png`）也由脚本重出：表格内容来自 `build_main_window` 追加的示例记录（28.4、54.0、72.5、95.0 mm），`fill_demo_defect_table` 按深度回填“判定”列，`capture_defect_table` 再把右键菜单压到“波幅”列上合成一张图。表格、统计面板和报告因此共用同一组示例数值。

配色改动会影响**全部**插图：改了 `app/common/theme.py`（色值、样式表）或 `app/common/plot_style.py`（绘图标题配色）之后，必须重跑一次脚本，否则说明书里边框、标题颜色会和实际界面对不上。

`gate_lines.png` 与 `cursor_ab.png` 的白线标注也由脚本绘制（`generate_annotation_screenshots`）：闸门框、门限、宽度、起点等位置按 A-Scan 的实时数据坐标折算成像素，游标位置取包络曲线的峰，所以标注始终和当前界面数值一致，不需要再用图像编辑器手工画。

`control_panel.png` 不是直接抓窗口：控制面板内容超过一屏，脚本把滚动区内容按顶层分组框之间的空隙切成左右两列，再拼到同一张画布上，因此插图中能一次看到全部分组。`workspace_analysis.png` 在 1700×1320 的窗口里同时展开统计、频谱和控制面板，抓完窗口后再按靠坞面板的叠放次序把子面板补画一遍——窗口较大时 Qt 会复用窗口自己的绘制缓存，被挡住或刚放大的区域可能只剩背景色。`settings_menu.png` 只截“设置”菜单弹出层，`filter_average.png` 截数字滤波器与信号平均两个分组，`shortcut_help.png` 截 F1 帮助窗口。

`report.png`（完整检测报告）是早期手工渲染的整页报告图，脚本不生成，仍保留改动前的绘图标题颜色；其余插图都由脚本重出。

少数插图依赖运行时数据，两次执行之间会有轻微差别，属于正常现象：`login_dialog`、`fft_panel`、`bscan_panel`、`cscan_panel`、`audit_dialog`、`report_config_dialog`、`control_panel`（随机信号、事件时间戳、个位数像素差异）。这类差异与功能无关，提交前可以还原。

截图必须在原生平台插件下渲染。`QT_QPA_PLATFORM=offscreen` 生成的图片不含文字，不能用于说明书；若不想让窗口闪现，可在脚本外把 `capture` 换成“`WA_DontShowOnScreen` + `grab()`”的版本。
